Engineered for Safety

Why developers choose CASI over cloud agents

No blind executions. No data leaks. Full deterministic testing in sandboxes with complete rollback control.

100% Local & Confidential

Native Ollama integration runs on your hardware with models like qwen2.5-coder:7b. Your proprietary codebase never touches cloud servers.

Zero-Network Docker Sandbox

Pytest executes in copy-on-run ephemeral Docker containers with disabled networking, strict PID limits, and a non-root user. Malicious code cannot phone home.

Ephemeral Git Worktrees

Multi-file patching and experimentation take place under .casi/worktrees/. Your active branch and unstaged changes remain completely clean.

Human Approval Gatekeeper

apply_patch is mathematically forbidden to the agent. Diffs are presented with syntax highlighting and require your direct [y] confirmation.

One-Key Rollback (/undo)

Applied a patch and changed your mind? Type /undo in interactive mode to restore the previous state immediately via the LIFO memento stack.

7 Specialized Roles

Task Evaluator refines user prompts and routes to specialized profiles: Fix, Create, Diagnose, Explain, Test Engineer, and more, consuming 0 decision steps.

Security Model

How CASI prevents accidental repo damage

1
Zero-step disambiguation

Task Evaluator & Refiner

Evaluates user intent against real repository layout. Disambiguates fuzzy requests into a refined_task and selects the optimal specialized persona before the decision loop begins.

2
Bounded loop

Read & Search Navigation

Uses safe read and ripgrep-style search tools. Paths outside the workspace and sensitive files (.env, keys) are blocked at the repository boundary.

3
Copy-on-run

Sandboxed Docker Verification

Patches are applied inside an isolated Git worktree. Pytest runs inside a temporary Docker container without internet access. If tests fail, CASI uses error sanitization and tries corrective iterations.

4
Human In The Loop

Human Approval Gatekeeper

The agent proposes the unified diff and pauses. You inspect the patch, choose whether to apply, save to disk, or reject. Only after confirmation does CASI write to your actual repository.

Quick Start

Up and running in 3 minutes

1

Install CASI

Clone the repository and install dependencies with Python 3.11+:

pip install -e ".[api,ui]"
2

Build the Docker Sandbox (Recommended)

Build the isolated, zero-network container used to verify test execution:

docker build -t casi-sandbox:latest -f docker/sandbox.Dockerfile .
3

Start Your First Supervised Session

Run a one-off fix or launch the interactive terminal REPL:

casi fix --repo . --task "Fix broken tests in test_auth.py"
casi interactive --repo .
